# 2026-10-27

## K8s Helm 部署（deploy/helm/apboa）

- 依据 `docker/docker-compose-simple.yml` + `docker-compose-console/execute/middleware(-run).yml`
  编写了 Helm chart，路径 `deploy/helm/apboa`，版本 0.1.0。
- 组件：mysql / redis / pgvector（StatefulSet 或 Deployment + PVC）、ollama（默认关）、
  console(3060) / runtime(3061) / proxy(3062) / gateway(hostNetwork) / websocket(3064) /
  file(无端口，仅 local 模式) / frontend(80，可选 Ingress)。
- 关键设计决定：
  - Service 名沿用 compose 的 `apboa-<组件>`，因为前端镜像内 `nginx.conf` 把控制台上游写死成
    `apboa-console:3060`；`namePrefix` 改名会 502。
  - 共享 `.apboa` 用单个 PVC（默认 RWX）；单节点用 `values-single-node.yaml` 改 RWO + NodePort。
  - 密码/JWT 由 Secret 模板生成，`lookup` 复用既有值，upgrade 不轮换。
  - gateway 保留 `hostNetwork: true` + `ClusterFirstWithHostNet`（数据面监听动态端口），
    PROXY_HOST/CONSOLE_HOST 改为 Service DNS（compose 里是 127.0.0.1）。
  - proxy 复刻安全加固：只读根文件系统 + /tmp emptyDir(Memory) + caps drop ALL/add
    SETUID/SETGID/CHOWN；`pids_limit` 在 K8s 无等价字段，已在模板注释说明。
  - APBOA_NODE_ID 用 downward API 的 `spec.nodeName`，保证同节点 runtime/proxy/gateway 同 nodeId。
  - db_init.sql 复制到 `files/` 并以 ConfigMap 挂到 `/docker-entrypoint-initdb.d`（仅首次初始化）。
- 验证方式：本机无 helm/kubectl，下载 helm v3.16.3 (darwin-amd64) 到 /tmp；
  `helm lint --strict` 通过，4 个场景（默认/单节点/外部中间件/local+file+ingress）`helm template`
  渲染后用 PyYAML 校验 YAML 合法性、卷挂载与探针端口一致性，全部无问题。未在真实集群 apply。
- 注意：该沙箱读取 >50KB 文件偶发被 SIGTERM 杀掉，改用管道喂 stdin 给 python 可绕过。
